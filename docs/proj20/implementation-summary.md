# 五个基础练习实现总结

五个练习来自赛题指定的 TanGram-rCore。固定参考提交、保留上游接口并复用官方测例。在租赁服务器上用 Rust 构建 RISC-V64 内核，用 QEMU TCG 执行测试。[参考版本与资料](references.md)

| 章节 | 实现与验证重点 |
|---|---|
| [ch3 系统调用计数](ch3-syscall-count.md) | 在当前任务控制块中先记录调用，再分发请求。查询 `TRACE` 时包含本次调用。字节读写只在当前任务的用户栈或程序区域内执行。宿主测试直接调用任务的处理入口。 |
| [ch4 地址空间](ch4-page-permissions.md) | 按 Sv39 权限翻译用户指针，拒绝未映射或权限不符的地址。匿名映射先检查范围，撤销前检查整个范围。未映射页导致撤销失败时，原有映射保持有效。 |
| [ch5 进程管理](ch5-process-scheduling.md) | `spawn` 从程序镜像创建独立进程。stride 调度选择累计值最小的就绪任务，同值沿用进队顺序。退出及 `exec` 更换地址空间后回收物理页。 |
| [ch6 文件系统](ch6-hard-links.md) | `linkat` 增加目录项并保留 inode，`unlinkat` 删除目录项，`fstat` 从已打开文件读取 inode 和链接数。最后一个链接与文件句柄均消失后，磁盘空间才可重用。 |
| [ch8 同步](ch8-deadlock-detection.md) | 为互斥锁和信号量分别维护等待和持有量。检测到危险请求时在进入实际队列前返回 `-0xDEAD`。仍可推进的请求保留正常等待和唤醒语义。 |

## 使用 AI 分析失败

- ch4 首次试做把计数数组放进待调度的进程结构，测试触发内核栈边界异常。AI 按异常位置核对局部栈使用，把计数放到堆上再运行。虚存组件另用注入测试证明映射失败会撤销本次已写入的叶子。
- ch5 连续创建进程时内存耗尽。AI 对照地址空间生命周期，补齐进程退出和更换程序后的回收，再跑官方基础与练习测试。
- ch8 参考版的单线程重复加锁用例会卡住。实现将拒绝放在同步原语入队之前，复跑时在 QEMU 串口观察到拒绝，用户程序可继续执行解锁并结束。宿主测试同时验证交叉等待与安全序列。
- 学习者亲自回答了重复加锁题和迁移题，AI 根据回答讲解了持锁者、释放条件和等待环。记录保留真实回答与尚未掌握的区别。[学习记录](learning-review.md)

每章都可以先按指导预测输出，再运行并解释证据。完整复跑命令、额外组件测试与打包验证见[验证记录](verification.md)。
